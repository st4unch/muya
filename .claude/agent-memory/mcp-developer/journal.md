## 2026-08-04 — `ssh_scp` MCP tool: agent SCP transfer (PRD ssh-scp, P1) SECURITY-CRITICAL

- **Done:** New `ssh_scp(alias,direction,localPath,remotePath,recursive?,extraArgs?)` MCP tool — same barrier as `ssh_run` (resolve_open → secret resolved in Rust → `run_with_injection(...,is_psmp)` PTY inject, PSMP 2FA-gate unchanged) PLUS two NEW guardrails since this is the first agent tool touching the LOCAL filesystem: (1) **AC3 local-path guardrail** — new `local_guard::resolve_local_scp_path` canonicalizes `localPath` and requires it be a child of a configured workspace root; catches `~/.ssh/id_rsa`/`/etc/passwd`, `..`-escapes, AND workspace-internal symlinks pointing outside (canonicalize resolves both `..` and symlinks in one pass) — runs BEFORE scp is ever invoked. ## 2026-08-04 — `ssh_run` PSMP 2FA/OTP hardening (PRD ssh-run-psmp-hardening, P1)

- **Done:** `ssh_run` no longer risks account-lockout on a PSMP RADIUS/2FA challenge. `pty.rs`: new `looks_like_challenge_prompt` (tail ends `passcode:`/`verification code:`/`one-time`/`otp:`), checked BEFORE the existing password-prompt check but ONLY when a new `is_psmp: bool` param on `run_with_injection` is true — direct-SSH callers pass `false` and get byte-for-byte the old behavior (AC4). On a challenge match: secret is withheld (never written to the PTY), and the outer poll loop kills the child immediately instead of waiting out `timeout`. `CommandOutput` gained `challenge_detected` + `injected` fields so callers can tell apart "injected normally" / "challenge withheld injection" / "timed out with no prompt at all" (the last is AC3's likely-RADIUS-push case). `broker.rs::handle_run`: `is_psmp = server.connection_type=="psmp"`; a `challenge_detected` result short-circuits to `err_resp(...)` with an ssh_open-pointing message (AC2); a PSMP timeout with neither `injected` nor `challenge_detected` adds an additive `"message"` field to the normal `ok:true` response (AC3) — direct responses unchanged. `muya_ssh_mcp.rs`: `ssh_run` tool description documents the PSMP+2FA limit and ssh_open fallback (AC5).
- **Decisions:** (1) Challenge-gating is strictly PSMP-only (`is_psmp` param) — direct SSH never runs the new classifier, so AC4 (no regression) holds by construction, not by careful pattern-tuning. (2) On challenge, kill immediately rather than waiting the 60s RUN_TIMEOUT — not explicitly required by the PRD but consistent with "don't burn an auth attempt / don't hang the agent" intent; non-critical, researched+decided. (3) AC3 hint modeled as an ADDITIVE `"message"` field on the existing `ok:true,timedOut:true` shape (not a new `ok:false` error) — a timeout isn't necessarily a failure, and the response contract (`{ok,stdout,exitCode,timedOut}`) stays backward compatible.
- **Refs:** `docs/prd-ssh-run-psmp-hardening.md` (mini-PRD, AC1-AC6), `src-tauri/src/pty.rs:54-70` (`looks_like_challenge_prompt`), `pty.rs::run_with_injection` (is_psmp param, challenge_flag), `pty.rs` tests `challenge_prompt_matches_2fa_shapes` / `ac2_psmp_challenge_prompt_withholds_injection` (real-PTY harness via `sh`, no Docker needed) / `ac4_direct_still_injects_on_passcode_prompt`, `broker.rs::handle_run` (~line 508-650), `bin/muya_ssh_mcp.rs:97` (ssh_run description). Commits: `d28d42f` (pty.rs), `8d93080` (broker.rs), `0c89b9d` (muya_ssh_mcp.rs description), `5696c7f` (PRD+step-output docs). Step output: `docs/prd-verify/step-output-P1.md`.
